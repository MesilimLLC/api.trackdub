The root is a thin orchestrator: `package.json` exposes unified scripts (`dev`, `build`, `deploy`, `db:*`, `test*`) that dispatch to Wrangler/Drizzle Kit/Vitest against two separate worker targets — the main API (entry `src/index.ts`, D1 binding `DB`, migrations under `drizzle/`) and the activation worker (separate entry, D1 binding with id `f95337b1-...`, migrations under `drizzle-activation/`). `wrangler.jsonc` declares the production bindings (D1, R2, version metadata) consumed by both the API and the test harness; `vitest.config.ts` runs the API suite in a real `workerd` process via `@cloudflare/vitest-pool-workers`, reading D1 migrations from `./drizzle` at config time and injecting them through a setup hook. `drizzle.config.ts` points at `src/db/schema.ts` as the single source of truth for the API's SQLite schema. The activation worker keeps its own schema/migrations/configs but shares the same TypeScript compiler settings, Zod validation, and D1 migration workflow. A second docs-rag worker is referenced via alternate Wrangler configs (`wrangler.docs-rag.jsonc`) and its own dev/deploy scripts.
