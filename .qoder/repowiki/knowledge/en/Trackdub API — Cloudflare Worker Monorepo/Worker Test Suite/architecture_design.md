Tests run via Vitest with `cloudflare:test` bindings (`env`) to spin up a real Hono app from `@/index` inside a workerd-like environment. Two test groups exist:
- Flat files under `test/` exercise individual concerns in isolation: auth middleware (`auth-middleware.test.ts`), CORS (`cors.test.ts`), error handling (`error.test.ts`), health/languages/session endpoints, and the DUBs job pipeline (`dubs.test.ts`, `docs-rag*.test.ts`).
- The `test/activation/` sub-directory contains an end-to-end activation suite (`activate.test.ts`, `admin.test.ts`, `config.test.ts`, `deactivate.test.ts`, `dev-license.test.ts`, `reactivate.test.ts`) that boots the full activation stack, seeds D1 rows through `helpers.seedLicense`, and drives HTTP requests against the live activation routes.

Shared bootstrap is split across two `apply-migrations.ts` files (root and under `activation/`) that call `applyD1Migrations` from `cloudflare:test` using the `__TEST_MIGRATIONS__` path set by the Vitest config. Runtime secrets are supplied via a local `TEST_SIGNING_KEY_PEM` / `TEST_SIGNING_PUBLIC_KEY_PEM` pair kept in `test-keys.ts` so they can be imported from both the Node-side Vitest process and the workerd test worker without pulling in Node-only tooling. Tests construct synthetic `Bindings` by merging `env as unknown as Bindings` with route-specific overrides (e.g. `DUB_PROCESSOR_ENABLED`).
