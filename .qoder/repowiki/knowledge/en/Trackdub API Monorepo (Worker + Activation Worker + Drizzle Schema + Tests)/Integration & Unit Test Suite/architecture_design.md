- Root-level `env.d.ts` augments `Cloudflare.Env` with `TEST_MIGRATIONS` so tests compile without a prior `wrangler types` run; `apply-migrations.ts` is a Vitest `beforeAll` hook that calls `applyD1Migrations(env.DB, __TEST_MIGRATIONS__)` once per worker process.
- Each top-level `*.test.ts` targets one module under `src/`: auth middleware, CORS, error handling, health, languages, sessions, dubs, and the docs-rag subsystem (split further into `docs-rag.test.ts` and `docs-rag-provenance.test.ts`).
- The `activation/` subdirectory groups integration tests for the activation feature behind its own `helpers.ts`, `test-keys.ts`, `env.d.ts`, and `apply-migrations.ts` setup, plus per-feature spec files (`activate`, `admin`, `config`, `deactivate`, `dev-license`, `reactivate`).
- Tests import the production Hono app via `@/index` or individual `@/middleware/*`, `@/routes/*`, `@/lib/*`, and `@/docs-rag/*` modules, mounting synthetic apps only where isolation is needed (e.g. `protectedTestApp` in `auth-middleware.test.ts`).
- External dependencies are stubbed at the lowest level: `fetch` is spied on for docs-rag HTTP calls, rate limiters are replaced by `stubLimiter`, and D1/R2 access goes through `cloudflare:test`'s in-memory bindings rather than real services.
