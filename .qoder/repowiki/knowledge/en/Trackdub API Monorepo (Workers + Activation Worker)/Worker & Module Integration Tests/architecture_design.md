Tests are organized by feature area at the `test/` root (route/middleware/lib modules) and as a sub-package under `test/activation/` for the activation Worker. Top-level files (`health.test.ts`, `cors.test.ts`, `error.test.ts`, `session.test.ts`, `dubs.test.ts`, etc.) import the production Hono app via `@/index` or `@/activation/index` and exercise it through `app.request(path, {}, bindings)` against the in-memory `cloudflare:test` runtime, while unit-style tests like `dubs-helpers.test.ts` import pure functions from `@/lib/dubs`. The `test/activation/` subtree has its own fixture layer: `helpers.ts` provides shared bindings cast to `ActivationBindings` plus `seedLicense`/`fingerprint` utilities that write directly into the test D1 DB; `test-keys.ts` holds an ephemeral ECDSA P-256 keypair (kept Node-free so it can be imported both by the Vitest config and inside workerd); `apply-migrations.ts` bootstraps schema state before each activation test file runs. Dependency direction is one-way: tests depend on `src/` via `@/...` aliases and never expose anything back to production code.
